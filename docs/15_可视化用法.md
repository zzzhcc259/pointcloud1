# 15 可视化用法

> **先说清楚：本项目的主菜单里没有可视化功能。**
>
> 这不是漏掉了，是**有意**的。这份文档讲三件事：
> 1. 为什么不放进去
> 2. 你想看的时候**怎么自己加**（完整代码，可以直接抄）
> 3. 不想改代码时，**用什么外部工具**看 `output/` 里的 PCD

---

## 一、为什么主菜单不放可视化

### 原因 1：它会让"算法"这件事变得不清晰

现在跑一次 VoxelGrid，输出是这样的：

```
  输入点数        : 30251
  输出点数        : 17847
  保留比例        : 0.590
  平均每体素点数  : 1.695
```

**你被迫去看数字。** 而看数字，你才会去想：

- 59% 保留率合理吗？（体素 2.0 / 点间距 1.47，$(1.47/2.0)^2 = 0.54$，合理）
- 平均每体素 1.695 个点，意味着有多少空体素？

**如果一开窗就看到点云变稀疏了，你就不想这些了。**

这不是道德说教，是学习效率问题：**图形让你"感觉懂了"，数字才让你"知道懂了"。**

### 原因 2：可视化会引入一个交互循环（死锁式）

PCL 的 `PCLVisualizer` 是**阻塞的** —— `viewer->spin()` 会占住线程，
直到你按 `q` 关掉窗口。

本来菜单是这样循环的：

```
显示菜单 → 读你的输入 → 跑算法 → 打印结果 → 打印"回车继续" → 显示菜单...
```

加了可视化就变成：

```
显示菜单 → 读你的输入 → 跑算法 → 弹窗 → 你关窗 → 打印结果 → 回车 → 显示菜单...
```

**这没问题**，但"程序没反应了"的错觉会让初学者困惑。

真正的麻烦在**多窗口**：如果你想"原图 vs 结果图并排对比"，
`spinOnce()` 的写法就复杂了（要自己维护一个渲染循环，`while (!viewer->wasStopped()) { ... }`）。

### 原因 3：它需要额外的一大堆 DLL

`visualization` 组件依赖 **VTK**，VTK 在 `E:\PointCloudEnv\PCL\3rdParty\VTK\bin` 下有
**310 个 DLL**。

`CMakeLists.txt` 里的 POST_BUILD 逻辑（第 135-195 行）**已经在拷这些 DLL 了**
（因为 `find_package` 里带了 `visualization` 组件）。

所以 DLL 不是问题 —— **但它是"为什么这个项目的 exe 旁边有 80 多个 DLL"的答案。**

### 那这个组件为什么还是留在 `find_package` 里

```cmake
find_package(PCL 1.15 REQUIRED COMPONENTS
    common io filters features search kdtree segmentation visualization)
                                                                  ↑ 这个
```

两个理由：

1. **让"你想加可视化"这件事成本最低** —— 改代码就行，不用动 CMake
2. **`segmentation` 里的某些部分也间接用到它**（历史原因，PCL 的组件依赖关系不太干净）

**测试过的事实**：把这个组件删掉，本项目也能编译（因为代码里没有 include
任何 `pcl/visualization/` 头文件）。删掉之后 `build\Release\` 里会少几十个 `vtk*.dll`。

## 二、PCLVisualizer 是什么

`pcl::visualization::PCLVisualizer` 是 PCL 的**3D 显示窗口**。

### 它其实是个 VTK 的壳

```
你的代码
   ↓
PCLVisualizer（PCL 的封装）
   ↓
vtkRenderer / vtkRenderWindow（VTK 的渲染器）
   ↓
OpenGL / DirectX（显卡驱动）
   ↓
窗口里的像素
```

**所以你看到的每一个点云窗口，背后都是 VTK 在画。**

这也解释了：
- 为什么依赖那么大（VTK 是个完整的科学可视化库，几百万行）
- 为什么窗口里的操作（旋转、缩放）和你熟悉的任何 3D 查看器差不多（VTK 的默认交互器）

### 最小可用例子

本项目的**环境探针**跑过这段代码，输出 `VIZ ok, renderers=1`：

```cpp
#include <pcl/visualization/pcl_visualizer.h>

pcl::visualization::PCLVisualizer viewer("最小例子");
viewer.setBackgroundColor(0.05, 0.05, 0.08);          // 深色背景
viewer.addPointCloud(cloud, "cloud");                 // 加点云
viewer.setPointCloudRenderingProperties(
    pcl::visualization::PCL_VISUALIZER_POINT_SIZE, 2, "cloud");
viewer.addCoordinateSystem(50.0);                     // 加坐标轴，长度 50mm
viewer.initCameraParameters();                        // 设默认视角
while (!viewer.wasStopped())                          // 主循环
{
    viewer.spinOnce(16);                              // 每帧处理一次事件
}
```

**四个关键点**：

| 调用 | 干什么 | 不调会怎样 |
|---|---|---|
| `addPointCloud` | 把点云加进场景 | 窗口全黑 |
| `addCoordinateSystem` | 画坐标轴 | 看不出朝向（**强烈建议加**） |
| `initCameraParameters` | 设默认相机位置 | 视角可能贴在物体内部，看起来很乱 |
| `while (!wasStopped()) spinOnce()` | 事件循环 | 窗口卡死（不响应鼠标） |

**`spin()` vs `spinOnce()`**：

- `viewer->spin()`：内部就是 `while (!wasStopped()) spinOnce()`，**一句顶四句**，但阻塞
- `viewer->spinOnce(ms)`：处理一次事件就返回，让你有机会做别的事（比如弹第二个窗口）

**本项目如果加可视化，用 `spin()` 就够**（一次只显示一个窗口）。

## 三、怎么自己加上去（完整步骤）

**目标**：在菜单里加一项「3.7 可视化：原始点云」，弹窗显示。

### 步骤 1：新建两个文件

`src/visualization/show_cloud.h`：

```cpp
#pragma once

#include <string>

#include "core/types.h"

namespace pcp
{
// 弹出一个窗口显示一份点云。blocking = true 时会一直等到你关窗。
// 返回 false 表示点云为空或创建窗口失败。
bool showCloud(const CloudConstPtr &cloud,
               const std::string &title,
               const std::string &cloudId);
}
```

`src/visualization/show_cloud.cpp`：

```cpp
#include "visualization/show_cloud.h"

#include <pcl/visualization/pcl_visualizer.h>

#include "core/console.h"

namespace pcp
{
bool showCloud(const CloudConstPtr &cloud, const std::string &title, const std::string &cloudId)
{
    if (!cloud || cloud->empty())
    {
        printError("点云为空，无法显示");
        return false;
    }

    pcl::visualization::PCLVisualizer viewer(title);
    viewer.setBackgroundColor(0.08, 0.08, 0.10);
    viewer.addPointCloud(cloud, cloudId);
    viewer.setPointCloudRenderingProperties(
        pcl::visualization::PCL_VISUALIZER_POINT_SIZE, 2, cloudId);
    viewer.addCoordinateSystem(50.0);          // 50mm 长的坐标轴
    viewer.initCameraParameters();

    printInfo("窗口已打开：" + title);
    printInfo("鼠标左键旋转 / 滚轮缩放 / 中键平移 / 按 q 或关窗退出");

    viewer.spin();                             // 阻塞到这里关窗

    return true;
}
}
```

### 步骤 2：加进 CMake

`CMakeLists.txt` 的 `target_sources` 里加：

```cmake
    src/visualization/show_cloud.cpp
```

**然后必须重新配置**：

```powershell
cmake -S . -B build
```

（新建了文件 → 改的是构建描述 → 必须 configure，见 [03](03_CMake入门.md)）

### 步骤 3：在菜单里注册

`src/menu/menu_items.cpp` 顶部加：

```cpp
#include "visualization/show_cloud.h"
```

然后加一个 action（放在 `actionInspectOriginal()` 附近）：

```cpp
void actionShowOriginal()
{
    printHeader("可视化：原始点云");

    std::string err;
    const pcp::CloudPtr cloud = pcp::loadCloud(pcp::originalScenePath(), err);
    if (!cloud)
    {
        pcp::printError(err);
        return;
    }

    pcp::showCloud(cloud, "原始点云（" + std::to_string(cloud->size()) + " 点）", "original");
}
```

最后在 `buildMenu()` 里加一行：

```cpp
items.push_back({"可视化", "显示原始点云", actionShowOriginal});
```

### 步骤 4：构建并运行

```powershell
cmake --build build --config Release
.\build\Release\PointCloudPractice.exe
```

选新出现的那一项。

### 验证清单

- [ ] 窗口弹出来了
- [ ] 能看到管道的圆柱形状和平板
- [ ] 左下角有 RGB 三色坐标轴（红=X、绿=Y、蓝=Z）
- [ ] 能旋转、缩放
- [ ] 关窗后回到菜单，程序没崩

**如果窗口黑屏** → `addPointCloud` 失败，检查 `cloudId` 是否为空。
**如果窗口一闪就关** → 少了 `while (!wasStopped())` 或 `spin()`。
**如果程序卡死** → 可能用了 `spinOnce()` 却没写循环。

## 四、给不同点云上不同颜色

### 方法 A：显示时指定颜色（最简单）

不用改点云，只在显示时告诉 viewer：

```cpp
viewer.addPointCloud(cloud, "cloud");
viewer.setPointCloudRenderingProperties(
    pcl::visualization::PCL_VISUALIZER_COLOR, 0.9, 0.3, 0.3, "cloud");   // 红
```

**`PCL_VISUALIZER_COLOR` 接受三个 0~1 的浮点数（R、G、B）**，不是 0~255。

**常见颜色**：

| 颜色 | RGB |
|---|---|
| 红 | `1.0, 0.2, 0.2` |
| 绿 | `0.2, 0.9, 0.3` |
| 蓝 | `0.2, 0.4, 1.0` |
| 灰 | `0.7, 0.7, 0.7` |
| 黄 | `1.0, 0.9, 0.2` |

### 方法 B：按高度着色（好看，而且有信息量）

```cpp
pcl::visualization::PointCloudColorHandlerGenericField<pcp::PointT>
    colorH(cloud, "z");                                  // 按 z 值映射颜色
viewer.addPointCloud<pcp::PointT>(cloud, colorH, "cloud");
```

**这样一眼能看出 z 的分布** —— 哪个点 z 高、哪个 z 低。

**但注意**：这是**相对着色**（自动把 min 映射到蓝色、max 映射到红色），
所以你看到的颜色**不能直接读出数值**。要读数看打印的坐标范围。

### 方法 C：把一块点云存成 RGB 字段（要换点类型）

**这是唯一能让"红色和其他颜色混在一份点云里"的方法。**

```cpp
#include <pcl/point_types.h>

pcl::PointCloud<pcl::PointXYZRGB>::Ptr colored(new pcl::PointCloud<pcl::PointXYZRGB>);
colored->reserve(cloud->size());
for (const auto &p : cloud->points)
{
    pcl::PointXYZRGB q;
    q.x = p.x; q.y = p.y; q.z = p.z;
    q.r = 255; q.g = 50; q.b = 50;         // 这里用 0~255 的 uint8
    colored->push_back(q);
}
viewer.addPointCloud<pcl::PointXYZRGB>(colored, "colored");
```

**注意两套 RGB 的差别**：

| 场景 | 类型 | 范围 |
|---|---|---|
| `setPointCloudRenderingProperties` | `double` | **0.0 ~ 1.0** |
| `PointXYZRGB` 的 `.r/.g/.b` | `uint8_t` | **0 ~ 255** |

**混了会出什么错**：传 `255, 0, 0` 给 `PCL_VISUALIZER_COLOR` → 全白（因为 255 远超 1.0，被截断）。

**这是 PCL 里最经典的 RGB 坑之一。**

## 五、显示两个点云并排对比

**这是最有用的用法**：原图 vs 结果图。

```cpp
pcl::visualization::PCLVisualizer viewer("对比");

// 左半边视口
int vp1 = 0;
viewer.createViewPort(0.0, 0.0, 0.5, 1.0, vp1);
viewer.setBackgroundColor(0.1, 0.1, 0.15, vp1);
viewer.addPointCloud(before, "before", vp1);
viewer.setPointCloudRenderingProperties(
    pcl::visualization::PCL_VISUALIZER_COLOR, 0.7, 0.7, 0.7, "before");
viewer.addText("原始 " + std::to_string(before->size()) + " 点", 10, 10, 16, 1.0, 1.0, 1.0, "t1", vp1);

// 右半边视口
int vp2 = 1;
viewer.createViewPort(0.5, 0.0, 1.0, 1.0, vp2);
viewer.setBackgroundColor(0.1, 0.1, 0.15, vp2);
viewer.addPointCloud(after, "after", vp2);
viewer.setPointCloudRenderingProperties(
    pcl::visualization::PCL_VISUALIZER_COLOR, 0.3, 0.9, 0.4, "after");
viewer.addText("结果 " + std::to_string(after->size()) + " 点", 10, 10, 16, 1.0, 1.0, 1.0, "t2", vp2);

viewer.addCoordinateSystem(50.0, vp1);
viewer.addCoordinateSystem(50.0, vp2);
viewer.spin();
```

**`createViewPort(x_min, y_min, x_max, y_max, id)`** 的参数都是 **0~1 的归一化屏幕坐标**：

```
 (0,1) ┌─────────────┬─────────────┐ (1,1)
       │   vp1       │    vp2      │
       │ 0,0,0.5,1   │ 0.5,0,1,1   │
 (0,0) └─────────────┴─────────────┘ (1,0)
```

**注意 y 轴朝上**（和图像坐标相反）。

**每个 `addPointCloud` 后面都要跟视口 id**，忘了就默认加到 vp0。

**这个技巧是"算法结果是否合理"最快的判断方式** ——
左右一看，点数变化、形态保留、飞点去哪了，全在眼里。

## 六、窗口里的鼠标和键盘

PCLVisualizer 用的是 VTK 的默认交互器：

| 操作 | 效果 |
|---|---|
| 鼠标**左键 + 拖动** | 旋转 |
| 鼠标**滚轮** | 缩放（朝光标位置缩放） |
| 鼠标**中键 + 拖动** | 平移 |
| 鼠标**右键 + 拖动** | 缩放（另一种） |
| **`r`** | 重置视角到 `initCameraParameters` 的状态 |
| **`q`** | 关闭窗口 |
| **`h`** | 打印帮助（弹出的窗口或控制台） |
| **`g`** | 显示/隐藏网格 |
| **`j`** | 截图（保存到当前工作目录） |
| **`+` / `-`** | 加快/减慢旋转速度 |
| **`p`** | 切换点云渲染模式（点/线/面） |

**最常用的两个：`r`（视角乱了就按）和 `q`（关窗）。**

**截图注意**：`j` 把 PNG 存到**当前工作目录**。如果你从 `build\Release\` 启动，
截图就跑到那儿去了。**这提醒你一件事：程序的工作目录不一定是项目根目录。**

## 七、不改代码怎么看 PCD（外部工具）

**如果你只是想看看 `output/` 里那几个 .pcd 长什么样，改代码太重了。**

### 工具 1：CloudCompare（最推荐）

- 官网：`https://www.cloudcompare.org/`
- 免费、开源、Windows 版直接下
- **能同时打开多个 PCD，并排对比**（左边选两个，右键 `Compare`）
- 能测距离、看法向、做配准

**用它的正确姿势**：

1. 打开 `data\scene_original.pcd`
2. 再打开 `output\voxel_leaf2.000.pcd`
3. 两个都勾选显示，用不同颜色区分
4. 缩放看：**降采样后的点是不是稀疏了，但形状还在**

### 工具 2：Meshlab

- 官网：`https://www.meshlab.net/`
- 更偏"面片网格"，但也能看点云
- 加载快，适合快速扫一眼

### 工具 3：VS Code + 插件

## 九、可视化的三个陷阱

### 陷阱 1：`is_dense = false` 的点云里有 NaN，可视化会崩

PCD 里如果有 `nan` 坐标（PCL 用 NaN 表示"无效点"），
`addPointCloud` 通常能跳过，但**坐标轴范围会算错**（NaN 参与 min/max 比较，结果不可预测）。

**本项目不会遇到**（生成的点和读回的点都没有 NaN），
但换成真实数据（尤其是带遮挡的深度图）就要小心。

**检查方法**：

```cpp
if (!cloud->is_dense)
{
    printWarn("点云包含无效点（NaN），可视化结果可能异常");
}
```

### 陷阱 2：点的数量太多会卡

**5 万个点很流畅，500 万个点会卡到没法操作。**

真实扫描的点云动辄几百万点。**看之前先体素降采样到 10 万以下。**

**这也是 `voxel_leaf` 在可视化部门最常见的用法**：不是"为了算法"，是"为了能看"。

### 陷阱 3：`spin()` 阻塞，多窗口要换写法

如果你想"每跑一个算法就开一个窗口，窗口全部保留"，
`spin()` 不行（第一个窗口关掉才继续）。

**要改成非阻塞**：

```cpp
pcl::visualization::PCLVisualizer::Ptr viewer(new pcl::visualization::PCLVisualizer("对比"));
// ... 加东西 ...
while (!viewer->wasStopped())
{
    viewer->spinOnce(16);
    // 这里可以加别的逻辑，比如按键盘切算法
}
```

**但这就变成"写一个小型 GUI 应用"了** —— 本项目刻意不做（见 [一、为什么主菜单不放可视化](#一为什么主菜单不放可视化)）。

## 十、一句话总结

**看图的时机**：

| 什么时候该看图 | 什么时候不该看 |
|---|---|
| 检查"形态还在不在"（降采样、裁剪后） | 判断参数对不对（**看数字**） |
| 对比"前后差异"（要做并排视口） | 判断算法有没有生效（**看点数**） |
| 给别人解释你在做什么 | 学习阶段（会削弱对数学的理解） |

**最佳搭配：先看数字理解发生了什么，再开窗口确认形态没被破坏。**
