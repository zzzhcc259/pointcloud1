# 在 Visual Studio 里运行这个项目

这篇只讲一件事：**怎么在 VS 里把这个程序跑起来。**

不讲 CMake 原理（那是 `03`、`04` 的事），不讲算法（那是 `08`～`13` 的事）。

---

## 一、先搞清楚：VS 里你打开的是什么

### 三种文件，别搞混

打开项目时你会见到三种文件，它们的作用完全不同：

| 文件 | 是什么 | 类比 |
|---|---|---|
| `CMakeLists.txt` | **构建说明书**。写了"有哪些源文件、要链接哪些库" | 菜谱 |
| `PointCloudPractice.slnx` | **VS 的工程目录**。CMake 读完成菜谱后生成它 | 菜单索引 |
| `PointCloudPractice.vcxproj` | **单个工程的配置**。一个 `.slnx` 里可以有好几个 | 菜单的某一页 |

**关键点**：`.slnx` 是 CMake **自动生成**的，不是你手写的。

所以：

- 你**不要**去双击 `.slnx` 编辑它
- 你**不要**去改 `.vcxproj`
- 真正的源头是 `CMakeLists.txt`，它一变，`.slnx` 就要重新生成

### 为什么不是直接打开 CMakeLists.txt

VS 确实支持"打开文件夹"直接读 `CMakeLists.txt`，但那种模式下很多功能有限。

这个项目走的是**标准流程**：

```
CMakeLists.txt  --(cmake 配置)-->  build\PointCloudPractice.slnx  --(VS 打开)-->  工程
```

所以你要打开的是 `.slnx`。

## 二、打开哪个文件

**要打开的文件（完整路径）：**

```
E:\dianyunxulian\build\PointCloudPractice.slnx
```

### 操作步骤

1. 打开 Visual Studio
2. 菜单栏点 **「文件」**
3. 选 **「打开」** → **「项目/解决方案」**
4. 在地址栏里粘贴：`E:\dianyunxulian\build`
5. 按回车
6. 找到 **`PointCloudPractice.slnx`**，点中它
7. 点右下角 **「打开」**

> **如果看不到 `.slnx` 文件**：
> 窗口右下角的文件类型筛选下拉框里，选「所有文件（\*.\*）」。
> 或者在文件名输入框里直接打 `PointCloudPractice.slnx` 然后回车。

### 注意：现在只有一个 `.slnx`，没有 `.sln`

`build\` 目录里的实际内容：

```
PointCloudPractice.slnx    ← 只有这个
```

**没有 `.sln`。** 因为 VS2026 用了新的解决方案格式 `.slnx`（XML 格式，比老的 `.sln` 文本格式更清爽）。

如果你在哪份文档里看到 `PointCloudPractice.sln`，那是老版本的写法，以磁盘上的 `.slnx` 为准。

## 四、三个项目分别是干什么的

打开后你会看到 **三个项目**，很容易懵。这里逐个说明：

| 项目名 | 是不是你的程序 | 干什么的 |
|---|---|---|
| **`PointCloudPractice`** | ✅ **是** | 你的程序，编译出 `PointCloudPractice.exe` |
| `ALL_BUILD` | ❌ 不是 | CMake 生成的"全建"目标。它的作用是"把下面所有项目都编一遍"，本身没有 exe |
| `ZERO_CHECK` | ❌ 不是 | CMake 生成的"检查"目标。`CMakeLists.txt` 一变，它就自动重新配置 |

（有的项目还会出现 `INSTALL`，也是 CMake 生成的辅助目标，这个项目没有。）

### 为什么 ALL_BUILD 会害你

**VS 默认把第一个项目设为启动项目**，很多时候就是 `ALL_BUILD`。

然后你按 F5，VS 会去启动 `ALL_BUILD`，但它**没有可执行文件**，于是弹：

```
无法启动程序 "E:\dianyunxulian\build\x64\Debug\ALL_BUILD"。
拒绝访问。
```

**这不是你代码的问题，是启动项目选错了。**

## 五、设为启动项目（关键一步）

### 为什么必须做

"启动项目"是 VS 的一个概念：**你按运行键时，它启动哪个程序。**

项目里有三个东西，默认可能不是你想要的那个。所以要手动指定。

### 怎么做

1. 在 **`PointCloudPractice`** 那一行上点**右键**
2. 在弹出的菜单里找 **「设为启动项目」**
3. 点它

### 怎么确认成功

成功的标志：**`PointCloudPractice` 这一行会变成粗体字**。

```
  ALL_BUILD              ← 正常字体
  PointCloudPractice     ← 粗体 ← 这就是启动项目
  ZERO_CHECK             ← 正常字体
```

### 这个东西需要每次设置吗

**不需要。** VS 会把它记在 `.slnx` 相关的用户设置里，下次打开还是它。

只有当你换了一份新的 `build\` 目录（重新配置过），才要再设一次。

## 七、运行

### 两个快捷键，区别很大

| 快捷键 | 名字 | 行为 |
|---|---|---|
| **`Ctrl + F5`** | 开始执行（不调试） | **推荐**。程序跑完，窗口停住等你按键 |
| `F5` | 开始调试 | 挂调试器。程序跑完窗口**立刻关闭**，你看不到输出 |

**日常用 `Ctrl + F5`。**

只有要打断点单步调试时才用 F5（见 `05_编译链接与调试.md`）。

### 运行时发生什么

1. VS 启动 `build\Release\PointCloudPractice.exe`
2. 弹出一个**黑色命令行窗口**
3. 窗口里显示菜单
4. **用鼠标点一下这个黑窗口**（让它获得键盘焦点，否则你打字没反应）
5. 输入编号，回车

> **为什么要点一下**：程序是从 VS 启动的，键盘焦点可能还在 VS 里。点一下黑窗口，输入才会进到程序里。

## 十、改了代码之后怎么办

### 看情况，分两种

| 你改了什么 | 要做什么 |
|---|---|
| 任意 `.cpp` 里的任意一行 | 只按 `Ctrl + Shift + B` |
| 任意 `.h` 里的任意一行 | 只按 `Ctrl + Shift + B` |
| **多了一个新的 `.cpp` 文件** | **先重新配置**，再编译 |
| **`CMakeLists.txt` 里加了一行** | **先重新配置**，再编译 |
| `CMakeLists.txt` 里删了文件 | 先重新配置，再编译 |

### 为什么第二种要重新配置

因为 `.slnx`（和里面的 `.vcxproj`）是 CMake **按 `CMakeLists.txt` 生成**的。

你在 `CMakeLists.txt` 里加了一个新文件，但旧的 `.vcxproj` 里还没有它。这时候直接编译，链接器会说"找不到那个函数的实现"（`LNK2019`）。

**必须让 CMake 重新生成一次 `.vcxproj`。**

### 怎么重新配置

在 VS 里最省事的方法是**关掉解决方案，用命令行重来**：

```powershell
cd E:\dianyunxulian
cmake -S . -B build -G "Visual Studio 18 2026" -A x64
```

然后重新打开 `build\PointCloudPractice.slnx`。

> **注意**：重新配置后，「设为启动项目」可能要重设一次。

## 十一、Debug 和 Release 怎么切换

VS 工具栏上有个下拉框，默认显示 `Debug` 或 `Release`：

```
[Debug ▼]  [x64 ▼]  [▶ 本地 Windows 调试器]
```

切换它，然后重新编译，产物会进入**不同的目录**：

| 配置 | 产物位置 | 库文件 |
|---|---|---|
| `Release` | `build\Release\` | `pcl_common.dll` 等 |
| `Debug` | `build\Debug\` | `pcl_common-gd.dll` 等（带 `-gd`） |

**两个目录的 DLL 不能混用。** 程序会自动找同目录的 DLL，所以别把两个目录的东西搅在一起。

**学算法用 Release**（快）。**要单步调试代码用 Debug**（能看到变量）。

## 十二、常见错误

### 错误 1：按 F5 报「无法启动程序 ALL_BUILD，拒绝访问」

**原因**：启动项目还是 `ALL_BUILD`。

**解决**：见第五节，右键 `PointCloudPractice` → 设为启动项目。

### 错误 2：黑窗口一闪就没了

**原因**：用了 `F5` 而不是 `Ctrl + F5`，程序跑完窗口自动关了。

**解决**：改用 `Ctrl + F5`。

如果换 `Ctrl + F5` 还是闪退，说明程序**崩溃了**，用 F5 跑一次看崩溃点（见 `05_编译链接与调试.md` 第 6 节）。

### 错误 3：提示「读不到 scene_original.pcd」

**原因**：程序的工作目录不对。

程序会自己找项目根目录：先看编译时写进去的路径（`PCP_PROJECT_DIR`），找不到就从当前目录往上搜 `CMakeLists.txt`。

**解决**：确认 `E:\dianyunxulian\data\scene_original.pcd` 这个文件真的存在。

如果文件丢了，在菜单里选 `1` 重新生成。

### 错误 4：改了 `.cpp`，编译了，但运行还是老结果

**原因**：忘了编译，或者编译到了另一个配置（Debug 编了，跑的却是 Release 的 exe）。

**解决**：看「输出」窗口确认生成成功，再确认工具栏的配置和你运行的 exe 目录一致。

### 错误 5：`Ctrl + Shift + B` 后报一大堆 `C1083`（找不到头文件）

**原因**：`CMakeLists.txt` 里的头文件搜索路径被改坏了，或者 PCL 路径不对。

**解决**：重新配置一次，看配置阶段有没有报错。详见 `03_CMake入门.md`。

## 十四、为什么七种算法只有一个程序

这个问题值得单独说一下，因为很多人第一次看到会疑惑。

**这个项目不是"七个算法七个 exe"，而是"一个 exe 带一个菜单"。**

### 真实工程就是这么做的

一个实际的点云处理系统（比如焊接机器人上位机），结构是：

```
一个程序
  ├─ 调用采集模块
  ├─ 调用预处理模块
  ├─ 调用分割模块
  └─ ...
```

**为什么？** 三个理由：

1. **数据要能在模块间传递**。预处理的结果直接交给分割，不用存文件再读回来。
2. **参数集中在一处**。不用维护七份配置。
3. **日志是一条链**。出问题能看完整流程。

### 什么时候真的会有多个 exe

PCL 官方自己就有几十个 exe（`pcl_viewer.exe`、`pcl_kdtree_search.exe`……），但那是**示例程序集**，每个演示一个 API，不是一个系统。

`CMakeLists.txt` 里要写很多个 `add_executable()`，每个配一个 `main()`。

**两种做法都不算错，用途不同：**

| 做法 | 适合场景 |
|---|---|
| 一个 exe + 菜单 | **真实系统**、要共享数据 |
| 多个 exe，各一个 main | **教学示例集**、演示单个 API |

这个项目选第一种，是因为它最终要朝着"一个系统"的方向走。

### 算法并没有被塞进一个文件

看结构就知道：

```
src\preprocessing\voxel_filter.cpp      ← 体素算法，独立文件
src\preprocessing\statistical_filter.cpp ← SOR 算法，独立文件
src\segmentation\ransac_plane.cpp        ← RANSAC 算法，独立文件
src\menu\menu_items.cpp                  ← 菜单，只负责"调哪个函数"
```

`menu_items.cpp` 里**没有一行算法代码**，只有"读参数 → 调用 → 打印结果"。

**算法各管各的，菜单只是一个入口。**
