# 00 学习路线

> 这份文档是**入口**。它不教你知识，它告诉你：按什么顺序、在哪一步停、怎么判断自己过了。

---

## 一、先说清楚：这个项目想让你学会什么

五件事，按"价值从高到低"排：

| # | 要学会的 | 为什么它最值钱 |
|---|---|---|
| 1 | **看懂一个多文件 C++ 工程的骨架**——谁能看见谁、为什么这么分文件 | 你以后拿任何一个开源点云项目（PCL 自身、各种焊接软件源码）都靠这个能力入门 |
| 2 | **CMake 到底在干什么**——`configure` 和 `build` 是两件事 | 90% 的「编译不过」其实是配置问题；不会 CMake 就只能复制别人的命令 |
| 3 | **编译 / 链接 / 运行时三者的区别** | `error C2065`、`LNK2019`、`0xC0000135` 三种报错分属三个阶段，处理方法完全不同 |
| 4 | **七个几何算法的"参数直觉"**——参数调大调小，结果往哪边变 | 这是你以后"根据不同场景选算法"的全部基础 |
| 5 | **Git 本地版本管理** | 敢改代码的前提是能退回去 |

**不在这五件事里的，本项目不教**：神经网络、ROS、Qt 界面、机器人运动学、焊接道次规划。
不是不重要，是学完这五件再说。

## 路线 A：只想先跑起来（约 30 分钟）

### A1. 四条命令（10 分钟）

打开 PowerShell：

```powershell
cd E:\dianyunxulian
cmake -S . -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Release
.\build\Release\PointCloudPractice.exe
```

> **不需要 `. E:\PointCloudEnv\env.ps1`。**
> `cmake` 在 `C:\Program Files\CMake\bin`（系统 `PATH` 里已有）；
> exe 依赖的 86 个 DLL 已被 `POST_BUILD` 拷到 `build\Release\` 里、和 exe 放在一起，
> Windows 加载 DLL 时最先找的就是 exe 自己的目录，所以直接跑就行
> （实测：只留 `C:\Windows\system32;C:\Windows` 的最小 `PATH`，退出码 `0`）。

**预期看到什么**：最后一条命令打印出一个中文菜单，等你输入编号。

**如果失败**：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `cmake : 无法将"cmake"项识别为...` | `CMake\bin` 不在 `PATH` | 要么重装 CMake 勾选"加进 PATH"，要么临时跑 `. E:\PointCloudEnv\env.ps1` |
| `CMake Error: Generator ... does not exist` | 你机器上没有 VS2026 | 把生成器换成 `"Visual Studio 17 2022"` |
| `Could not find PCL` | `PCL_ROOT_DIR` 指向的路径不对 | `cmake -S . -B build -G "..." -A x64 -DPCL_ROOT_DIR="你的PCL路径"` |
| 编译时一堆 `error C1189 ... PCL was likely compiled without AVX` | vcpkg 的另一套 PCL 串进来了 | 正常情况下本项目已经用 `CMAKE_VS_GLOBALS` 挡住了；如果还报，见 [14_项目练习与故障排查.md](14_项目练习与故障排查.md) |
| 程序一启动就退出（退出码 `-1073741515`） | exe 旁边缺 DLL（比如把 exe 拷到别处运行了） | 在 `build\Release\` 里原地运行；或临时 `. E:\PointCloudEnv\env.ps1` 设 `PATH` |

### A2. 跑一遍菜单（15 分钟）

按顺序输入这几个数字，每次回车：

```
2      ← 看原始点云长什么样（点数、坐标范围、平均点间距）
3      ← 体素降采样（一路回车用默认参数）
9      ← RANSAC 平面分割
10     ← 欧氏聚类
11     ← 看 output 目录里有什么
0      ← 退出
```

**观察这四件事**（这是路线 A 的全部目的）：

1. 菜单 2 打印出的**平均点间距约 1.47 mm** —— 记住这个数，后面所有算法的参数都绕不开它
2. 体素降采样后点数从 30251 掉到 **17847**
3. RANSAC 找到的平面**内点数是 2213**，法向量不是 (0,1,0) —— 说明它找错了（这是故意的教学点，见 [12_RANSAC平面分割.md](12_RANSAC平面分割.md)）
4. 欧氏聚类分出 **2 簇**：25921 点的管道 + 4131 点的平板

**A 阶段算过了的标准**：你能不看文档，自己再跑一遍、并且知道 `output\` 里新增了哪几个文件。

## 路线 B：搞懂项目是怎么搭的（3~4 天，主线）

这是本项目**真正的主线**。每天 1~1.5 小时，分四天。

### Day 1 —— 多文件 C++（读 + 改）

**读**：[02_项目目录与多文件C++.md](02_项目目录与多文件C++.md)

**做**（只做这一件事，20 分钟以内）：

打开 `src\core\algo_result.h` 和 `src\segmentation\ransac_plane.cpp`，回答两个问题：

1. `RansacPlaneOptions` struct 定义在 `.h` 里还是 `.cpp` 里？为什么不能定义在 `.cpp` 里？
2. `runRansacPlane` 这个函数的名字在几个文件里出现过？分别出现的是"声明"还是"定义"？

然后做一个小动作：把 `src\core\console.cpp` 里 `printRule()` 打印的横线长度从 70 改成 40，
重新编译，运行，看菜单的分隔线变短。

**Day 1 算过了的标准**：你能说清楚"如果我把 `runRansacPlane` 的实现从 `.cpp` 里删掉但保留 `.h` 里的声明，
会发生什么错误、错误在哪个阶段报出来"。答不出来就回去重读文档里"未定义引用"那一节。

### Day 2 —— CMake（读 + 故意搞坏）

**读**：[03_CMake入门.md](03_CMake入门.md) 和 [04_CMakeLists逐行解释.md](04_CMakeLists逐行解释.md)

**做**：把 `CMakeLists.txt` 里的 `project(PointCloudPractice ...)` 改成 `project(MyTest ...)`，
重新配置（`cmake -S . -B build ...` 那条），然后看 `build\` 目录里的 `.sln` 文件名变成了 `MyTest.sln`。

再做一件事：**故意破坏一次**。在 `target_sources(...)` 里删掉一行 `src/preprocessing/voxel_filter.cpp`，
重新构建，把它报的 `LNK2019` 完整抄下来。

**Day 2 算过了的标准**：你能不看文档，说出下面四个词各是谁在做、先后顺序是什么：
`configure` / `generate` / `build` / `link`。

### Day 3 —— 编译链接调试（读 + 断点）

**读**：[05_编译链接与调试.md](05_编译链接与调试.md)

**做**：用 Visual Studio 打开 `build\PointCloudPractice.slnx`
（注意是 `.slnx` 不是 `.sln`，VS2026 用的是新的解决方案格式；
怎么打开、怎么设启动项目，见 [16_在VS里运行.md](16_在VS里运行.md)），
在 `src\core\cloud_io.cpp` 的 `loadCloud()` 里那一行 `pcl::io::loadPCDFile` 上按 F9 下断点，
F5 启动，在菜单里选 2，看程序停在那里，鼠标悬停看 `absPath` 的值。

**Day 3 算过了的标准**：你能解释"为什么 Debug 版的 exe 有 3 MB、Release 版只有 200 KB"，
以及"为什么改了 `.cpp` 只需 build，改了 `CMakeLists.txt` 必须重新 configure"。

### Day 4 —— Git

**读**：[06_Git本地版本管理.md](06_Git本地版本管理.md)

**做**：`git init` → `git add .` → `git commit -m "初始版本"`，
然后**故意改坏一个文件**，用 `git diff` 看改了什么，用 `git restore` 恢复。

**Day 4 算过了的标准**：你能不看文档，把"我刚才改坏了什么"用 `git diff` 找出来并恢复。
**这一条比前三天加起来都实用。**

## 路线 C：搞懂算法（按需跳读，不要求顺序）

不要从 08 读到 13。**按你手上的问题去查**：

| 你的问题 | 读哪份 |
|---|---|
| 点云到底是什么？PCD 文件里存了什么？ | [01_原始点云数据.md](01_原始点云数据.md) |
| `pcl::PointCloud<PointXYZ>` 的 `width`/`height`/`is_dense` 是干嘛的？ | [07_PCL点云数据结构.md](07_PCL点云数据结构.md) |
| 点太多了跑不动，怎么变少？ | [08_VoxelGrid体素降采样.md](08_VoxelGrid体素降采样.md) |
| 点云里有飘在外面的噪点，怎么清掉？SOR 和 ROR 该用哪个？ | [09_统计滤波与半径滤波.md](09_统计滤波与半径滤波.md) |
| 我想知道某个点周围有哪些邻居 | [10_KDTree邻域搜索.md](10_KDTree邻域搜索.md) |
| 我只想看管子上某一段，其它都扔掉 | [11_PassThrough坐标裁剪.md](11_PassThrough坐标裁剪.md) |
| 我想把平板从点云里单独抠出来 | [12_RANSAC平面分割.md](12_RANSAC平面分割.md) |
| 我想把管子和平板分成两块 | [13_欧氏聚类.md](13_欧氏聚类.md) |

### 每个算法文档的读法

每份都有 13 节，**不要全读**。第一次读只读这四节：

- **第 1 节 解决什么问题** —— 30 秒，决定你要不要继续
- **第 2 节 直观几何解释** —— 有图有例子，这段最重要
- **第 5 节 关键参数** —— 记住参数名
- **第 10 节 动手练习** —— 直接去改参数跑一遍

**第 3 节数学、第 7 节逐段代码解释**：等你真的要改这段代码的时候再回来看。

**算"这个算法我懂了"的标准**（每个算法都适用）：

> 不看文档，你能说出「我把这个参数从 A 改成 B，输出点数会变多还是变少」，
> 然后跑一遍，**猜对了**。
>
> 猜对一次就算懂了一半；能说出为什么，算全懂。

## 三、节奏建议

### 每次坐下来学，用这个模板

```
1. 先跑一遍，看到当前状态          （3 分钟，不要跳过）
2. 读一小节文档                    （15 分钟）
3. 改一个地方、重新编译、看变化     （15 分钟）
4. 在纸上或笔记里写一句"我发现了..." （2 分钟）
```

**第 4 步不要省。** 你改成什么参数、点数从多少变成多少 —— 这个数字记下来，
比读三遍文档都管用。

### 什么时候该停

- 连续两次编译失败且看不懂报错 → 停，去 [14_项目练习与故障排查.md](14_项目练习与故障排查.md) 按症状查，或直接把报错原文贴给我
- 读文档超过 20 分钟还没动手 → 停，去跑程序
- 觉得"这算法好抽象" → 停，去菜单里改参数跑，先看数字变化，再回来看公式

## 四、这个项目学完之后

你会具备这些能力（都是可验证的）：

1. 拿到一个 CMake + PCL 的开源项目，能自己配起来、编译、跑起来
2. 看到一个 `LNK2019`，知道是"声明了但没实现"或"实现没加进构建"
3. 拿到一份陌生的点云，知道第一步该看什么（点数、间距、范围），
   然后决定先降采样还是先滤波
4. 知道 RANSAC 抽不到正确模型时该调哪个参数
5. 改坏了代码能退回去

**你还不会的**（正常，需要另外的项目）：

- 真实线激光数据的标定与去噪
- 焊缝坡口的精确几何建模（张口宽度 b、坡口深度 h 的鲁棒提取）
- 多道焊的道次划分与焊枪姿态
- 机器人可达性、轨迹插值、碰撞检测

这四件事是下一阶段的事，不要在这个项目里找。
