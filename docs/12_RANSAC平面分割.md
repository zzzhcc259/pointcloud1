**这是本项目最值得细读的一份文档。** 因为 RANSAC 是唯一一个
"参数设对了也对、设错了也给你一个答案"的算法 —— 它不会报错，只会**给你错的答案**。

---

## 一、这个算法解决什么问题

一句话：**在一堆点里，找出"最像某个几何形状"的那一批点。**

具体到平面：给你 30251 个点，其中有一块平板、一根管子、一堆飞点，
**把平板的 4131 个点挑出来**。

### 为什么这件事很难

如果点云是干净的（只有平板），那就简单了：随便取三个点定一个平面，剩下全在内。

但真实情况是：

- 有别的物体（管道）也在那里
- 有飞点（噪声）
- 而且**你不知道哪个点是平板上的**

### 一个天真的想法，以及它为什么不行

**天真想法**：既然平板在 y=200，那 `y > 190` 的点就是平板。

**为什么不行**：

- 这个前提是"你已经知道平板在哪" —— 那就不需要算法了
- 换一个场景、换一个摆放角度，这个结论就废了
- 真实的焊缝点云里，你**根本不知道**坡口面在哪

**RANSAC 的价值在于：它不需要你先告诉它"东西在哪"。**

## 二、直观几何解释

### 核心思想：三个点定一个平面

平面上**任意三个不共线的点**，唯一确定这个平面。

```
        ●
       ●  ●          ← 随便挑 3 个点，它们决定一个平面
      ●    ●
     ●      ●
```

那反过来：**如果我从这堆点里随机挑 3 个，它们恰好都是平板上的点，
那么这 3 个点定出来的平面，就是平板本身。**

有了这个平面，我就能数：**有多少点落在这个平面附近？**

- 如果 4131 个点都在附近 → **这肯定是真正的平板**
- 如果只有 50 个点在附近 → **这 3 个点是碰巧凑在一起的，不是平面**

### RANSAC 的完整循环

```
重复 N 次：
    1. 随机挑 3 个点
    2. 用它们算出一个平面
    3. 数一数：有多少点离这个平面 < 阈值？
       （这些点叫"内点 inliers"）
    4. 如果这次的内点数比之前所有尝试都多，就记住这个平面

最后：输出内点数最多的那个平面
```

**就这么简单。** 没有任何优化、没有导数、没有迭代收敛。

### 为什么它有效：概率

关键在于：**平板占了 13.65% 的点**（4131 / 30251）。

随机挑 3 个点，**全都**落在平板上的概率是：

$$0.1365^3 = 0.002543 \approx 0.25\%$$

看起来很小。但**挑 1000 次，至少中一次的概率**是：

$$1 - (1 - 0.002543)^{1000} = 1 - 0.997457^{1000} \approx 92.2\%$$

**这就是 RANSAC 的全部魔力：单次成功率很低，但试很多次就几乎必然成功。**

### "假平面"是什么（本项目的真实陷阱）

管壁是个圆柱面。**圆柱面在某个点附近，看起来非常平。**

```
   圆柱面（半径 R）
        ╭──────────╮
      ╭─╯          ╰─╮
     ╱                ╲
    │      ← 中间这一段，看起来就像一块平板
    │
```

数学上：距切点弧长 $s$ 处，圆柱面偏离切平面的距离（矢高）是

$$\Delta \approx \frac{s^2}{2R}$$

本项目 $R = 50$ mm。要让 $\Delta < 1$ mm（我们的距离阈值），

$$s < \sqrt{2 \times 50 \times 1} = 10 \text{ mm}$$

**也就是说：管壁上有 ±10 mm 的一段，其"凸起"只有 1 mm。**
一个 1 mm 厚的平面带，就能把这一段管壁上的所有点框进去。

**结果**：RANSAC 会找到一个"贴着管壁的假平面"，内点有 2000 多个 ——
**比平板小，但比任何随机 3 点凑出的都大。**

如果你的迭代次数不够抽到真平板，**这就是你会拿到的答案**。

## 三、数学原理

### 3.1 平面方程

三维空间里的平面写成：

$$a x + b y + c z + d = 0$$

其中 $\vec{n} = (a, b, c)$ 是**法向量**（垂直于平面），必须归一化：$|\vec{n}| = 1$。

**$d$ 的含义**：把原点 $(0,0,0)$ 代进去得 $d$。
所以 $|d|$ 是**原点到平面的距离**（在 $|\vec n|=1$ 的前提下）。

### 3.2 点到平面的距离

点 $p = (x_0, y_0, z_0)$ 到平面 $ax+by+cz+d=0$ 的距离：

$$D = \frac{|a x_0 + b y_0 + c z_0 + d|}{\sqrt{a^2+b^2+c^2}}$$

**因为法向量已经归一化**（分母 = 1），所以简化为：

$$D = |a x_0 + b y_0 + c z_0 + d|$$

**RANSAC 的全部计算就是这个式子。** 对每个点算一次，比阈值，计数。

### 3.3 三个点怎么算出平面

设三点 $p_1, p_2, p_3$。

**第一步**：两个边向量

$$\vec{u} = p_2 - p_1, \quad \vec{v} = p_3 - p_1$$

**第二步**：叉积得法向量

$$\vec{n} = \vec{u} \times \vec{v}$$

**第三步**：归一化 $\vec{n} \leftarrow \vec{n} / |\vec{n}|$

**第四步**：$d = -(\vec{n} \cdot p_1)$

**注意**：如果三点共线，$\vec{u} \times \vec{v} = \vec{0}$，**算不出平面**。
这就是为什么 PCL 会打印：

```
[pcl::SampleConsensusModelPlane::isSampleGood] Sample points too similar or collinear!
```

它检测到这三个点共线，直接丢弃这次采样。

### 3.4 需要迭代多少次（核心公式）

设：

- $w$ = 内点占全部点的比例（本项目的平板：$w = 4131/30251 = 0.1365$）
- $s$ = 确定模型需要的最小点数（平面 $s = 3$）
- $p$ = 我们想要的**成功率**（通常 0.99）

则需要的迭代次数：

$$N = \frac{\log(1 - p)}{\log\left(1 - w^s\right)}$$

代入本项目：

$$N = \frac{\log(0.01)}{\log(1 - 0.1365^3)} = \frac{-4.605}{-0.002546} \approx 1809$$

**所以理论上需要约 1809 次迭代。**

### 3.5 但实测 1000 次失败、1200 次成功

这是本项目最值得琢磨的地方。实测（固定环境、重复 3 次，结果完全一致）：

| 迭代次数 | 平面内点数 | 法向量 | 找到的是什么 |
|---|---|---|---|
| 800 | 1976 | `(-0.0025, 0.6480, 0.7616)` | 管壁上的假平面 A |
| 900 | 1976 | `(-0.0025, 0.6480, 0.7616)` | 同上 |
| **1000** | **2213** | `(-0.0020, 0.3851, 0.9229)` | 管壁上的假平面 B |
| **1200** | **4131** | `(-0.0000, -1.0000, 0.0000)` | **真正的平板（y=200）** |
| 2000 | 4131 | `(-0.0000, -1.0000, 0.0000)` | 真正的平板 |
| 5000 | 4131 | `(-0.0000, -1.0000, 0.0000)` | 真正的平板 |

**为什么"重复 3 次结果完全一致"？**

因为 PCL 内部的随机数生成器在**没换种子**的情况下是**固定序列**。
所以：

- 第一次跑 1000 次迭代，用的是序列的第 1~1000 个数
- 第二次跑，还是同样的第 1~1000 个数 → **结果必然一样**

**这既是好事也是坏事：**

- 好：结果可复现，好教学、好排查
- 坏：**你测一次就以为"就是这样"，其实换台机器可能不一样**

**为什么 1000 次不够、1200 次够了？**

理论值 1809 是个**期望**。实际需要多少次取决于随机序列"什么时候碰巧抽中"。
这个固定序列在第 1000~1200 次之间的某处**第一次**抽到三个全在平板上的点。

**你要记住的不是"1000 不行 1200 行"这个具体数字**，而是：

> **迭代次数必须大于 $w^s$ 的倒数所决定的量级。
> 内点占比越小、模型需要的点数越多，迭代次数要越夸张。**

### 3.6 内点占比低时的恐怖增长

$$N \propto \frac{1}{w^s}$$

| 内点占比 $w$ | $s=3$ 需要迭代 | 说明 |
|---|---|---|
| 50% | 35 | 很轻松 |
| 30% | 169 | 轻松 |
| 13.65%（本项目平板） | **1809** | 要上千次 |
| 5% | 36,800 | 三万多次 |
| 1% | **4,600,000** | 四百六十万次 —— 没法用 |

**这就是 RANSAC 的软肋**：它假设"内点占多数或相当比例"。
如果平面只占 1% 的点，纯 RANSAC 就废了。

**工业上的应对**：
- 先裁剪（PassThrough）缩小范围，提高内点占比
- 用 PROSAC（按质量排序采样）
- 或者改用别的思路（Hough 变换、区域生长）

## 五、关键参数

### `distanceThreshold` —— 距离阈值（mm）

**这个参数决定"多近算在平面上"。**

- 太小 → 真正平面上的点（因为噪声）也被判为外点
- 太大 → 把附近别的东西也吸进来

**经验值**：**1 ~ 3 倍平均点间距**。

本项目的平均点间距是 **1.470 mm**（菜单 2 可以看到），所以：

| 阈值 | 相当于 | 效果 |
|---|---|---|
| 0.5 mm | 0.34 倍 | 太严，只剩最贴的点 |
| **1.0 mm** | **0.68 倍** | 本项目默认值 |
| 2.0 mm | 1.36 倍 | 开始吸进管壁 |
| 5.0 mm | 3.4 倍 | 明显过宽 |

### `maxIterations` —— 迭代次数上限

**这是最容易被低估的参数。** 见第三节 3.5。

本项目默认 **1000**，但**在这个场景下不够**（会找到假平面）。

### `probability` —— 期望成功率

PCL 的 RANSAC 会用这个值**动态判断"还要不要继续迭代"**：

```cpp
// PCL 内部逻辑（简化）
const double k = std::log(1.0 - probability) / std::log(1.0 - std::pow(w, s));
if (iterationsDone > k) break;    // 够了，提前停
```

也就是说：**如果当前已经找到的内点比例很高，PCL 会提前结束，不等 maxIterations 用完。**

所以 `maxIterations` 是**上限**，不是"一定跑这么多次"。

设 0.99 意味着"我有 99% 的把握找到最优解"。

### `optimizeCoefficients` —— 事后精修

`true` 时，PCL 在找到最优内点集后，会**用这些内点重新做一次最小二乘拟合**。

**为什么重要**：RANSAC 最后那个平面是"随机挑的 3 个点"定的，
**这 3 个点都有噪声**，所以那个平面是"凑巧能框住很多点"的，不是"最贴合"的。

最小二乘精修之后，平面会移到"所有内点的平均位置"，**法向量更准**。

**建议**：**永远开 `true`**。代价很小，效果好。

## 六、参数变大变小的效果（实测）

### 迭代次数的影响（阈值 1.0，固定）

| 迭代 | 内点数 | 法向量 Y,Z 分量 | 结论 |
|---|---|---|---|
| 800 | 1976 | 0.6480, 0.7616 | 假平面 A（斜的） |
| 900 | 1976 | 0.6480, 0.7616 | 假平面 A |
| 1000 | 2213 | 0.3851, 0.9229 | 假平面 B（斜的） |
| **1200** | **4131** | **-1.0000, 0.0000** | **真平板** |
| 2000+ | 4131 | -1.0000, 0.0000 | 真平板（稳定） |

**关键读数**：**法向量的 Y 分量是不是接近 ±1。**

- `b ≈ ±1` → 平面水平 → 平板
- `b` 在 0.3 ~ 0.9 之间 → 斜的 → **假的**

**这是最快的判断方法。** 我们的代码里已经把它做成了自动提示：

```cpp
if (std::abs(std::abs(b) - 1.0) < 0.1)
{
    printInfo("法向量接近 ±Y 轴 —— 说明找到的是水平平板，符合预期");
}
else
{
    printInfo("法向量不是 Y 轴方向 —— 可能找到的并不是平板（例如被管壁上的近似平面吸走了）");
}
```

### 距离阈值的影响（迭代 1000，固定 —— 注意此时找到的是假平面）

| 阈值 | 内点数 | 说明 |
|---|---|---|
| 0.2 | 927 | 太严，只剩管壁上最贴的一小条 |
| 0.5 | 1421 | |
| 1.0 | 2213 | 默认 |
| 2.0 | 3090 | |
| 3.0 | 3830 | |
| 5.0 | **5128** | **超过平板总数** → 明显混入了管壁 |

**阈值越大内点越多，这是单调的。** 但要注意：

**内点最多 ≠ 结果最好。** 阈值 5.0 时内点 5128，
但那个"平面"是把管壁和平板混在一起勉强凑出来的 —— 法向量 `(0.37, 0.93)` 是斜的。

**所以判断标准不是"内点数最多"，而是"内点数多 且 法向量物理上说得通"。**

### 阈值在真平板上的影响（迭代 5000）

| 阈值 | 内点数 |
|---|---|
| 0.5 | 4131 |
| 1.0 | 4131 |
| 2.0 | 4131 |
| 3.0 | 4131 |

**完全不变。** 为什么？

因为我们的平板是**几何上完美的平面** + 噪声只有 0.05 mm（`noiseSigma`）。
所有点离真实平面的距离都在 0.05 mm 以内，远小于最严的 0.5 mm 阈值。

**这是合成数据的"好"也是"坏"**：

- 好：结果干净，容易验证
- 坏：**看不出阈值的影响**，学不到"阈值该怎么调"

**想体会阈值的影响，去做第十节的练习 4。**

## 七、代码逐段解释

打开 [`src/segmentation/ransac_plane.cpp`](../src/segmentation/ransac_plane.cpp)。

### 第 1 段：参数检查（第 26–41 行）

```cpp
if (opt.distanceThreshold <= 0.0)
{
    result.summary = "距离阈值必须为正，未执行";
    printError("距离阈值必须大于 0");
    return result;
}
if (opt.maxIterations < 10)
{
    printWarn("迭代次数太少（<10），找到正确平面的概率很低");
}
```

**注意第二个不是 `return`，是 `printWarn`。**

为什么？因为"迭代 5 次"**技术上能跑**，PCL 不会拒绝。
它只是**几乎肯定给出垃圾结果**。

**这个区别很重要**：

- 参数**非法**（阈值 ≤ 0）→ 拒绝执行
- 参数**合法但不合理**（迭代太少）→ 警告，但让你跑

**让用户自己看到"跑了但结果是垃圾"，比直接拦住更有教育意义。**

### 第 2 段：准备容器（第 47–50 行）

```cpp
pcl::ModelCoefficients::Ptr coefficients(new pcl::ModelCoefficients);
pcl::PointIndices::Ptr inliers(new pcl::PointIndices);
```

这两个是 PCL 的**输出容器**：

- `ModelCoefficients` —— 装"模型参数"。对平面来说是 4 个数 `[a, b, c, d]`
- `PointIndices` —— 装"内点的下标"

**注意它们是"空的壳"**，内容由 `segment()` 填。

**为什么是 `Ptr` 而不是对象**：PCL 的接口统一用智能指针，
避免拷贝大数组（`PointIndices` 里有几千个 `int`）。

### 第 3 段：配置（第 52–64 行）

```cpp
pcl::SACSegmentation<PointT> seg;
seg.setOptimizeCoefficients(opt.optimizeCoefficients);
seg.setModelType(pcl::SACMODEL_PLANE);
seg.setMethodType(pcl::SAC_RANSAC);
seg.setDistanceThreshold(static_cast<float>(opt.distanceThreshold));
seg.setMaxIterations(opt.maxIterations);
seg.setProbability(opt.probability);
```

**PCL 的设计很精妙：模型类型 和 采样方法 是分开的两个参数。**

| 参数 | 本项目取值 | 可选的其它值 |
|---|---|---|
| `setModelType` | `SACMODEL_PLANE` | `SACMODEL_CYLINDER`、`SACMODEL_SPHERE`、`SACMODEL_LINE`... |
| `setMethodType` | `SAC_RANSAC` | `SAC_LMEDS`（抗噪强但慢）、`SAC_MSAC`、`SAC_RRANSAC` |

**同一个模型可以配不同采样方法，同一个采样方法也能处理不同模型。**

这就是为什么代码里**只需要改两行**，就能从"找平面"变成"找圆柱"：

```cpp
seg.setModelType(pcl::SACMODEL_CYLINDER);
seg.setRadiusLimits(45.0, 55.0);   // 圆柱还要额外给半径范围
```

**本项目没有实现圆柱分割**（见 README 的"未实现"清单），
但这是管道场景里最该补的一个 —— 因为管道本来就是圆柱。

### 第 4 段：执行（第 67–68 行）

```cpp
seg.setInputCloud(input);
seg.segment(*inliers, *coefficients);
```

**一行完成整个 RANSAC 循环。** PCL 内部大致是：

```cpp
// PCL 内部（伪代码）
best_inlier_count = 0;
for (int iter = 0; iter < max_iterations; ++iter)
{
    // 1. 随机采 3 个点
    sample = randomSample(3);
    if (isCollinear(sample)) { PCL_WARN("too similar"); continue; }

    // 2. 算模型
    model = computePlane(sample);

    // 3. 数内点
    inliers = countInliers(model, distance_threshold);

    // 4. 更新最优
    if (inliers.size() > best_inlier_count) { best = model; best_inlier_count = inliers.size(); }

    // 5. 判断能不能提前停
    if (iter > neededIterations(best_inlier_count / n, probability)) break;
}
```

**注意第 5 步**：一旦内点比例够高，它会**提前结束**。
所以"跑 5000 次"实际可能只跑了 1500 次就停了。

### 第 5 段：没找到平面（第 70–77 行）

```cpp
if (inliers->indices.empty())
{
    result.summary = "没有找到任何平面";

    printInfo("试试把距离阈值调大，或换一个场景（例如 1 管道+平板）");
```

**什么时候会走到这里**：

- 点云只有 2 个点（连 3 个都不够）

**这是真实会遇到的** —— 项目早期的探针程序里，我们用 5 个共线点测过，
PCL 打印了一堆 `Sample points too similar or collinear!` 然后返回空。

### 第 6 段：手写拆点（第 79–107 行）—— 本文件最值得看的部分

PCL 提供了 `pcl::ExtractIndices` 来"按下标抠点"。代码里**故意不用**，而是手写：

```cpp
std::vector<bool> isInlier(input->size(), false);
for (const int idx : inliers->indices)
{
    isInlier[static_cast<size_t>(idx)] = true;
}
for (size_t i = 0; i < input->size(); ++i)
{
    if (isInlier[i]) { plane->push_back(input->points[i]); }
    else             { rest->push_back(input->points[i]); }
}
```

**这段代码在教你一件事：PCL 的"分割"不神秘。**

什么叫"把点分成两堆"？就是：

1. 准备一个和点数一样长的 `bool` 数组，全 `false`
2. 把内点的下标位置设成 `true`
3. 遍历一遍，按 `true`/`false` 分到两个容器

**`ExtractIndices` 做的就是这件事**，只是封装起来了。

**为什么要手写**：因为如果你只会 `extract.setIndices(...)`，
你就永远不知道"内点"到底是什么。**手写一遍，你就懂了。**

**注意两个细节**：

```cpp
std::vector<bool> isInlier(input->size(), false);
```

用 `vector<bool>` 而不是 `vector<char>`：`vector<bool>` 是**位压缩**的，
30251 个 bool 只占约 3.8 KB 而不是 30 KB。

```cpp
plane->reserve(inliers->indices.size());
```

**`reserve` 预分配内存。** 不写也能跑，但会反复"容量不够→重新分配→拷贝"，
慢好几倍。**处理大数据时这是必须的。**

### 第 7 段：把系数翻译成人话（第 109–132 行）

```cpp
const auto &c = coefficients->values;
const double a = c[0], b = c[1], cc = c[2], d = c[3];

std::cout << "  方程 : " << ... << a << "·x + " << b << "·y + " << cc << "·z + " << d << " = 0\n";
std::cout << "  法向量 : (" << ... << a << ", " << b << ", " << cc << ")"
          << "   长度 = " << std::sqrt(a * a + b * b + cc * cc) << "\n";
std::cout << "  原点到平面的距离 : " << ... << std::abs(d) / std::sqrt(a*a + b*b + cc*cc) << " mm\n";
```

**这是本文件最有用的部分。**

`coefficients` 里就是 4 个数字，直接打印出来是 `(-0.0020, 0.3851, 0.9229, -49.33)`，
**没人看得懂**。翻译一下：

| 打印项 | 含义 | 怎么用 |
|---|---|---|
| 方程 | `a·x + b·y + c·z + d = 0` | 抄进论文/笔记 |
| 法向量长度 | 应该是 1.0000 | **如果不是 1，说明系数没归一化，有 bug** |
| 原点到平面距离 | `|d| / |n|` | 平板应该约 200 mm（y=200） |

**"法向量长度应该是 1" 是一个免费的自检。** PCL 保证归一化，
所以如果打印出 `0.9876`，那一定有问题。

### 第 8 段：自动判断"找到的是不是平板"（第 125–132 行）

```cpp
if (std::abs(std::abs(b) - 1.0) < 0.1)
{
    printInfo("法向量接近 ±Y 轴 —— 说明找到的是水平平板，符合预期");
}
else
{
    printInfo("法向量不是 Y 轴方向 —— 可能找到的并不是平板（例如被管壁上的近似平面吸走了）");
}
```

**这四行代码是本项目里"最像工程师写的"部分。**

因为 RANSAC **不会告诉你它找错了**。它只会给你一个"内点数不错"的结果。

**必须有人（或代码）去检查结果的物理合理性。**

注意 `std::abs(std::abs(b) - 1.0)`：为什么要**两层** `abs`？

因为法向量指向哪边是随机的 —— 可能是 `(0, 1, 0)` 也可能是 `(0, -1, 0)`，
取决于 RANSAC 抽到的三个点是怎么排列的。

所以：

- `b = 1` → `|b| - 1 = 0` → 通过
- `b = -1` → `|b| - 1 = 0` → 也通过

**这是处理"方向不确定"的标准写法。**

### 第 9 段：保存两个结果（第 150–160 行）

```cpp
std::ostringstream tag;
tag << "th" << std::fixed << std::setprecision(2) << opt.distanceThreshold
    << "_iter" << opt.maxIterations;

result.output_path = saveOutput("ransac_plane_plane", tag.str(), plane);
const std::string restPath = saveOutput("ransac_plane_rest", tag.str(), rest);
```

**为什么输出两个文件**：

- `..._plane_...` 你要的答案
- `..._rest_...` **剩下的东西** —— 往往同样有用

比如"找坡口面"：找到坡口面之后，`rest` 里就是管壁和底面。
**下一轮 RANSAC 就在 `rest` 上跑。**

**这才是"多平面分割"的真实做法**：一次找一个，从剩下的里再找。

## 九、检查结果是否合理

### 检查 1：法向量长度必须是 1.0000

不是 1 → PCL 有问题，或者你用了没归一化的系数。

### 检查 2：法向量方向和物理场景对得上

本场景的平板是水平的（`y = 200`），所以法向量必须是 `(0, ±1, 0)`。

**如果 `b` 在 0.3 ~ 0.9 之间，你拿到的是管壁上的假平面。**

### 检查 3：内点数和"你预期那个物体有多少点"对得上

- 平板 4131 点
- 如果输出 4131 → 完美
- 如果输出 2213 → 假平面
- 如果输出 5128 → 阈值太宽，混了东西

### 检查 4：`d` 和场景的几何尺寸对得上

平板在 `y = 200`，所以 `|d|` 应该约 200。

**如果 `|d|` 是 49.33（实测中假平面的值）**，那说明它找到了一个离原点 49.33 mm 的平面 ——
管道半径正好是 50，**这就暴露了它贴的是管壁**。

### 检查 5：内点 + 剩余 = 输入

```
4131 + 26120 = 30251 ✅
```

**每次都要对一遍。** 不对就说明拆点逻辑有 bug。

### 检查 6：看 `rest` 文件

`ransac_plane_rest_*.pcd` 里应该是"管道 + 飞点"。

如果 `rest` 里还有大片平板状的点 → 分割不干净（可能要找第二个平面）。

## 十一、常见报错与调试

| 现象 | 原因 | 解决 |
|---|---|---|
| `Sample points too similar or collinear!` 刷屏 | 点太少或点几乎共线 | 正常现象，换个场景或加点 |
| `No samples could be selected!` | 同上，所有采样都失败 | 同上 |
| `Error segmenting the model! No solution found.` | 没找到任何内点 | 调大阈值，或检查点云是不是空的 |
| 内点数很大但法向量很怪 | **找到了假平面** | 增大迭代次数 |
| 内点数 = 0 | 阈值太小 | 调到 1~3 倍点间距 |
| 内点数 = 全部点 | 阈值太大 | 调小 |
| 法向量长度 ≠ 1 | 系数没归一化 | 检查 PCL 版本，或自己归一化 |
| 程序崩溃 | `coefficients->values` 为空时直接访问 `c[0]` | 先检查 `!coefficients->values.empty()` |

### 一个隐藏的坑：`coefficients->values` 可能是空的

如果 `segment()` 失败，`coefficients->values` 会是**空 vector**。

我们的代码在 `inliers->indices.empty()` 时就提前 `return` 了，所以不会走到访问 `c[0]`。
**但如果有人删掉那个检查，就会崩。**

**教训**：**用之前先检查容器非空。** 这是 C++ 的基本功。

## 十二、与管道焊缝点云处理的联系

### RANSAC 在焊缝流程里的位置

```
点云 → 预处理 → 【RANSAC 找平面】→ 特征提取 → 道次 → 轨迹
```

具体要找哪些平面（以管道对接环焊缝为例）：

| 要找的 | 对应几何 | RANSAC 模型 |
|---|---|---|
| 管壁 | 圆柱面 | `SACMODEL_CYLINDER`（本项目未实现） |
| 坡口斜面 | 圆锥面 / 斜面 | `SACMODEL_PLANE`（近似） |
| 钝边端面 | 平面 | `SACMODEL_PLANE` |
| 工件台面 | 平面 | `SACMODEL_PLANE` |

**一个真实的多平面分割流程**：

```
1. RANSAC 找台面 → 内点扔掉（rest 保留）
2. 在 rest 上 RANSAC 找管壁（圆柱）→ 拟合轴线
3. 在 rest 上 RANSAC 找坡口面 × 2（左右的斜面）
4. 用这些面和轴线求交线 → 焊缝路径
```

**本项目的 RANSAC 是这套流程的原型。** 你学会了"一次分割"，
"多次分割"只是在循环里重复而已。

### 焊缝场景里 RANSAC 最大的问题

**坡口面往往只占点云的很小一部分。**

一条 10 米长的管道焊缝，坡口面可能只占整片扫描的 2%~5%。

**按第三节 3.6 的表，5% 需要 3.7 万次迭代；2% 需要 57 万次。**

**所以工业上不会直接对整片点云跑 RANSAC 找坡口。** 实际做法是：

1. 先粗略定位焊缝（用图像、用 CAD 模型、用人工标记）
2. **PassThrough 裁出焊缝附近的一小段** → 坡口面占比提高到 30%~50%
3. 在**小范围**里跑 RANSAC → 只需要几十次迭代

**这就是为什么 PassThrough（第 11 份文档）和 RANSAC 是连着用的。**

## 十三、在真实扫描数据中的局限

### 局限 1：真实平面不是真的平

本项目平板是**数学上完美的平面**。真实的钢板有：

- 轧制公差（0.1~0.5 mm 不平度）
- 焊接变形（局部翘曲可达几毫米）
- 装夹应力

**后果**：阈值设 1 mm 时，真实钢板可能只有一部分点在"平面"上；
或者阈值必须放宽到 3~5 mm，然后就会吸进别的东西。

**没有哪个阈值同时合适** —— 这是真实数据最难的地方。

### 局限 2：点云密度不均

线激光扫描时：

- 正对传感器的区域点很密
- 斜视区域点很稀（间距可能是几倍）

**后果**：RANSAC 偏向"点密"的区域 —— 因为那里内点自然多。

**应对**：先做均匀降采样（VoxelGrid），让密度一致。

### 局限 3：初始答案依赖随机序列

第三节 3.5 说了：同一个程序、同样参数，重复跑结果**完全一致**（因为随机序列固定）。

**但这是一种错觉**：换一台机器、换一个 PCL 版本、换一个编译选项，
随机序列可能就变了，结果也就变了。

**工程上应该**：

- 用足够大的迭代次数（留 2~3 倍余量）
- 或者显式设置随机种子，让行为可复现

**本项目的做法**：不设种子（用 PCL 默认），所以在本机上可复现，
但**不能保证在别的机器上一样**。**这一点必须知道。**

### 局限 4：只找"最像"的那一个

RANSAC 输出**内点最多的那个模型**，不输出所有模型。

如果场景里有两块同样大的平板，**你只会拿到其中一块**，
而且拿到哪一块取决于随机序列。

**应对**：分割 → 移除内点 → 再分割，循环。

### 局限 5：它不判断"这个平面有没有物理意义"

RANSAC 会觉得"贴着管壁的一条带子"是一个**好平面** —— 因为内点确实很多。

**它不知道那是圆柱，也不知道你要的是平板。**

**所以永远要有人（或代码）去检查法向量、位置、和内点数是否符合预期。**
本项目第 8 段那四行 `if (std::abs(std::abs(b) - 1.0) < 0.1)` 就是干这个的。
